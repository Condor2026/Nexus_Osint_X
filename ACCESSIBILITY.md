# Accessibility Statement — Nexus_Osint_X

Nexus_Osint_X is a self-hosted OSINT radar built as a prototype. We want it to be usable by as many people as possible, including users with disabilities. This statement describes our accessibility commitment, supported environments, known limitations, and how to report barriers.

Nexus_Osint_X is a data-heavy, map-centric tool. It was built with the time and means available, and full accessibility is an ongoing effort, not a finished guarantee.

## Our commitment

We aim to follow the principles of **WCAG 2.1 Level AA** where feasible for the web dashboard, and to keep the interface usable with a keyboard and with assistive technologies. Because the core value of Nexus_Osint_X is its data, we also aim to make that data reachable through non-visual channels (REST API, exports) when the visual layer is a barrier.

We treat accessibility as part of the review process. Reports and ideas are welcome via issues. Note: this project does not accept pull requests (see README); accessibility diagnostics and suggestions are welcome through issues.

## Supported environments

| Environment | Status |
|-------------|--------|
| Modern browsers (Chrome, Firefox, Edge, Safari — last 2 versions) | ✅ Supported |
| Keyboard-only navigation | ✅ Supported |
| Screen readers (NVDA, JAWS, VoiceOver, Orca) | ⚠️ Partially supported |
| High-contrast / forced-colors mode | ⚠️ Partially supported |
| Zoom up to 200% | ✅ Supported |
| Mobile / responsive layout | ⚠️ Partially supported |
| WebGL disabled (2D Canvas fallback) | ✅ Supported (reduced feature set) |
| Terminal / TTY with screen reader | ⚠️ Partially supported |

## Accessibility features

- Language switch **ES/EN** (🌐) persisted in `localStorage`.
- Keyboard shortcuts documented in the README: `/` focus search, `r` refresh, `j` toggle JARVIS, `+`/`-` zoom, `0` reset view, `n` next critical alert, `c` toggle cities, `Esc` close JARVIS.
- Visible focus and standard form controls in filters, tabs, and the JARVIS panel.
- **Text alternatives exist for the data**: the REST API (`/api/*`) and 12 export formats (CSV, JSON, NDJSON, GeoJSON, KML, XLSX, Markdown, HTML, IP lists, group IPs, ZIP) expose the same information shown on the map and charts.
- The JARVIS panel includes a **text summary** generated by rules, so the situation can be read without interpreting charts.
- Sound alarms are **optional** (🔔) and require user opt-in; no audio plays by default.
- A **2D Canvas fallback** exists when WebGL or deck.gl is unavailable.
- Defanged indicators (e.g. `hxxp://ejemplo[.]com`) reduce accidental interaction with malicious links.
- Dark and light basemaps are available (Carto light/dark), letting users choose higher contrast backgrounds.

## Known limitations

- **The 3D globe and flat map (deck.gl)** are visual-first (WebGL/Canvas). Points, arcs, correlations, and satellites are **not fully accessible to screen readers**. The same data is available via `/api/map`, `/api/events`, `/api/correlations`, and exports.
- **Charts in JARVIS** (threat index gauge, ATT&CK radar, stacked areas, sparklines, concentric rings) rely on Canvas and are not screen-reader friendly. Numeric values are exposed via `/api/analytics`, `/api/kpis`, and `/api/attack`.
- **Animated background (neural net)** and live WebSocket updates may be distracting. There is no dedicated "reduce motion" toggle yet; users can stop sweeps and mute alarms, but animation is not globally disableable.
- **Color** carries meaning on the map (domain color, severity halo, group type). Legend and labels exist, but color-blind users may need to rely on the event card and exports.
- **Dark theme contrast** may not meet AA on every element; improvements are tracked.
- **Alarm sounds** are audio-only; a visual critical-event indicator exists but is not equivalent.
- **Basemap tiles** (Carto, Esri, OpenStreetMap) are third-party and outside our control.
- **Third-party data sources** (RSS, APIs, Telegram public channels) are not under our control; missing or blocked sources reduce what is shown, not the accessibility of what is shown.

## Reporting an accessibility barrier

If you encounter an accessibility barrier, please open an issue:

- **GitHub:** open an issue at `https://github.com/Condor2026/Nexus_Osint_X/issues` with the label `accessibility` (or mention "accessibility" in the title).
- Include:
  - The page, view, or feature affected (dashboard, JARVIS, map, Detector, export…)
  - Your browser, OS, and assistive technology (if any)
  - Steps to reproduce the barrier
  - The impact on your ability to use the feature
  - Any suggested improvement (optional)

For security-sensitive matters, do not open a public issue: see [SECURITY.md](SECURITY.md).

We aim to acknowledge accessibility reports within **7 days** and to address confirmed barriers in a reasonable timeframe, prioritizing those that block core functionality (reading events, using JARVIS, exporting data).

## Alternatives when the visual layer is a barrier

- Use the **REST API** (`/api/events`, `/api/map`, `/api/kpis`, `/api/analytics`, `/api/ioc`, `/api/detector`, …).
- Use **exports** (`/export/{fmt}`) to get the data in CSV, JSON, NDJSON, GeoJSON, KML, XLSX, Markdown, or HTML.
- Use the **JARVIS text summary** for a rules-based reading of the current situation.
- Use the **IOC search** (`/api/ioc`) and **IP search** (JARVIS) without relying on the map.

## Continuous improvement

Accessibility is considered when changing the dashboard, JARVIS, and exports. Since this is a prototype and pull requests are not accepted, the most effective way to improve accessibility is to **report concrete barriers with reproduction steps** via issues. Ideas that make the data reachable without the visual layer are especially welcome.
